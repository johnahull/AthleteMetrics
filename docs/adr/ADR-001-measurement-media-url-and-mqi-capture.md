# ADR-001: Measurement media_url and MQI Capture

**Date**: 2026-10-06
**Status**: Accepted

First ADR in `docs/adr/`. Implements AM-FEAT-015 (branch `feature/mqi-entry-ui`; migrations 0146-0149).

## Context

Coaches score Movement Quality Index (MQI) screens per athlete: 8 movement patterns plus 4 transition items, each scored on an ordinal 0-3 scale, with optional per-pattern notes and a reference video. The existing measurement pipeline assumed positive values, wrote event results directly, and treated every metric as eligible for percentiles, benchmarks and leaderboards. Ordinal rubric scores do not fit those assumptions, and a video link is sensitive data for minors.

## Decision

1. **Metrics (0146)**: seed 12 ordinal metrics `MQ_*` (0-3) and two derived totals, `MQI_TOTAL` (8 patterns, 0-24) and `MQ_TRANSITION_TOTAL` (4 `MQ_TRANS_*`, 0-12). Unit is `score`. The calculated totals cannot be entered manually.
2. **Generic `measurements.media_url` (0147)**: nullable column, https-only public host (`isSafePublicUrl`), no credentials or whitespace, stored in canonical form, max 2048 chars (also a DB CHECK, added `NOT VALID` then validated). Generic rather than MQI-specific so other metrics can attach media later. It is kept out of public payloads in two ways: CSV, LLM and COPPA exports build explicit field lists without it, and the redaction helpers in `packages/api/utils/measurement-redaction.ts` (`omitMediaUrl`, `omitMediaUrlFromRows`, `stripMediaUrlDeep`) are applied by the parent view (`parent-routes.ts`), the unified cross-org views (`global-athlete-service.ts`) and public report snapshots (`report-service.ts`). The general measurement queries return it on purpose in authenticated org-scoped views: rows of organizations the requester belongs to, and personal (no-organization) rows only to their own athlete or a site admin (list and `GET /api/measurements/:id`); `filterMode=all` is the union of those, not a cross-organization view.
3. **Latest-event selection (0148)**: `calculationConfig.sourceSelection = 'latest_event'` on both totals. Only verified scores count. For a date, the latest event wins, ranked by event start time (any event outranks scores without one; entry order never decides), and a total is computed only when all its source metrics come from that same event. If the latest event is incomplete, the existing total for that date is deleted.
4. **Zero values only for MQ metrics**: 0 is accepted for MQ codes (prefix match in `packages/shared/peer-comparison-exclusions.ts`) whose `site_metrics.validation_min <= 0`, with a range and whole-number check; every other metric keeps the positive-only rule, including existing metrics seeded with `validation_min = 0` (`packages/shared/measurement-value-validation.ts`). The same check runs on the import write path.
5. **Exclusion from comparisons**: MQ metrics are excluded from peer percentiles, report percentiles / team averages / rankings / composite index, most-improved, benchmarks (create and update) and leaderboards (`packages/shared/peer-comparison-exclusions.ts`).
6. **Event writes via `MeasurementService`**: event data entry goes through the service (unit handling, validation, derived calculator) instead of direct inserts. MQ scores are one row per (athlete, metric, event), edited in place under an advisory lock, with a partial unique index as backstop (0149), and always use the event's calendar date. No athlete notifications or achievements before results are published. The panel saves one athlete atomically with `PUT /api/events/:eventId/athletes/:userId/movement-quality`; `DELETE /api/events/:eventId/measurements/:measurementId` also exists. Frozen events remain frozen.
7. **Notes and UI**: per-pattern notes go in `measurements.notes`. UI is the `MovementQualityPanel` dialog on event data entry.
8. **Coach-only MQ scores and clips**: athletes may not enter MQ scores (R2) or attach clips (R1). Both rules are a role **allowlist**: only `coach`, `org_admin` and `site_admin` may write an MQ code (the `isMovementQualityMetric` predicate, including moving an entry onto an MQ metric) or set a non-empty `mediaUrl`; every other role (athlete, parent, guest) and a missing role are denied. Omitting or clearing `mediaUrl` (null or empty string) is allowed for every role. Enforcement lives in two places. (a) `MeasurementService` (`assertCanEnterMetric`, `assertCanAttachClip`) on create, batch and update, so every route that writes through it is covered: `POST` / `PUT /api/measurements` answer **403** `{ message }`, and `updateMeasurement` fails closed when no role is passed. (b) The storage-based import paths, which write through `storage.createMeasurement` and call `assertCanEnterMetric` themselves: the CSV measurement import and the photo (OCR) import reject a non-allowed MQ row as a **per-row error** in the import result (the request itself succeeds, it is not a 403), checked before athlete matching or creation; `POST /api/import/review-decision` answers **403** for a decision on an MQ item by a non-allowed role and leaves the item pending (that route is currently shadowed by `POST /api/import/:type`, which is registered first; the guard keeps it safe if the order changes). The imports do not take `mediaUrl`. Event measurement routes, including the panel save, are limited to event managers (site admin, or coach / org admin of the event's organization) and map the two permission errors to 403 as a safeguard. The event service enforces the allowlist itself too: it writes through `MeasurementService` with the manager role the route resolves, and a call without a role fails closed. Event writes are limited to athletes who belong to the event's organization (400; a per-item error in bulk). The photo (OCR) import cannot import MQ scores at all (its extractor only recognizes timed/jump metrics and it rejects values <= 0), so the zero rule in decision 4 applies to the CSV path, not OCR. In the UI, event data entry renders only for event managers (`canManageEvent` in `packages/web/src/lib/event-permissions.ts`, shared with the event page), and the athlete self-entry forms do not list MQ metrics: `SelfEntryForm.tsx` (My Measurements) and, for athletes, `athlete-measurement-form.tsx`.

Rejected: a dedicated MQI table (duplicates measurement history, permissions and exports); raw-value percentiles for ordinal scores (not meaningful).

## Consequences

### Positive
- MQI reuses measurement permissions, history, audit and derived-metric machinery.
- `media_url` is reusable; exports never select it, and the views that pass rows through strip it.
- Zero-valid metrics are possible without loosening validation for timed/jump metrics.

### Negative
- Redaction is allowlist-by-call-site: a new read path that exposes measurements must use an explicit field list without `mediaUrl` or one of the redaction helpers.
- The four event measurement mutation routes (`POST`, `POST .../bulk`, `DELETE .../:measurementId`, `PUT .../movement-quality`) share one limiter: STANDARD tier, 100 per 15 minutes per signed-in user (previously MUTATION, 20 per 15 minutes per IP, on POST and bulk). Very large sessions can still reach it.
- Down migrations are manual (`apply-manual-migrations.js` skips `*_down.sql`): 0146 down refuses while MQ data or configuration references the metrics, 0147 down destroys stored links, 0148 down removes latest-event selection, 0149 down drops the unique index.

### Neutral
- Open item M4 (unverified athlete MQ scores never produce a total): with decision 8 an athlete-role session cannot create or edit an MQ score on any write path that exists today (MeasurementService routes, event routes, CSV, OCR, review decision), and MQ scores written by coach / org admin / site admin sessions are verified, so the totals' verified-only rule needs no trigger change. The claim rests on the session role; see the known issues below.
- Known issues left open (pre-date AM-FEAT-015, not fixed here): the session role is taken from the user's first organization, not the organization of the row being written, so a user who is a coach in one organization and an athlete in another is treated as a coach everywhere; `POST /api/measurements` does not restrict parent and guest sessions to their own data for non-MQ metrics; the import review queue is held in memory and is not filtered by organization. The CSV import also has no general athlete block (only the MQ rule). A teammate athlete of the same organization can see clips in the org-scoped measurement lists (the spec only rules out public and export payloads). Fixed alongside this work although they pre-date it: personal (no-organization) measurements were returned to any signed-in user by `GET /api/measurements?filterMode=personal|all` and `GET /api/measurements/:id`, and the event routes accepted athletes from other organizations.
- v1 out of scope: score bands, report surfacing, BTB / AM-FEAT-014 quadrant, video upload (URL only), structured hard-fault.
- Manual migration numbers 0144/0145 are reserved for AM-FEAT-016.
