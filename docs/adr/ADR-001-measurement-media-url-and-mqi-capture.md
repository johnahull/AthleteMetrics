# ADR-001: Measurement media_url and MQI Capture

**Date**: 2026-10-06
**Status**: Accepted

First ADR in `docs/adr/`. Implements AM-FEAT-015 (branch `feature/mqi-entry-ui`; migrations 0146-0149).

## Context

Coaches score Movement Quality Index (MQI) screens per athlete: 8 movement patterns plus 4 transition items, each scored on an ordinal 0-3 scale, with optional per-pattern notes and a reference video. The existing measurement pipeline assumed positive values, wrote event results directly, and treated every metric as eligible for percentiles, benchmarks and leaderboards. Ordinal rubric scores do not fit those assumptions, and a video link is sensitive data for minors.

## Decision

1. **Metrics (0146)**: seed 12 ordinal metrics `MQ_*` (0-3) and two derived totals, `MQI_TOTAL` (8 patterns, 0-24) and `MQ_TRANSITION_TOTAL` (4 `MQ_TRANS_*`, 0-12). Unit is `score`. The calculated totals cannot be written by hand on any path (create, storage imports and event entry, moving a measurement onto a total, editing a calculated total).
2. **Generic `measurements.media_url` (0147)**: nullable column, https-only public host (`isSafePublicUrl`), no credentials or whitespace, stored in canonical form, max 2048 chars (also a DB CHECK, added `NOT VALID` and not validated in 0147, because the migration runner applies the file in one transaction and a `VALIDATE` would scan the table under `ADD COLUMN`'s ACCESS EXCLUSIVE lock; the new column is all NULL and new writes are checked; 0147 sets `lock_timeout = '5s'`). Generic rather than MQI-specific so other metrics can attach media later. It is kept out of public payloads in two ways: CSV, LLM and COPPA exports build explicit field lists without it, and two redaction helpers in `packages/api/utils/measurement-redaction.ts` are applied: `omitMediaUrlFromRows` by the parent view (`parent-routes.ts`) and the unified cross-org views (`global-athlete-service.ts`), and `stripMediaUrlDeep` by public report snapshots (`report-service.ts`). Clip read rule (decided): in authenticated org-scoped reads a row keeps its `mediaUrl` only for a site admin, the athlete who owns the row, or a coach / org admin of the row's organization (memberships read from the database, not the session role); a teammate athlete, a parent, a guest or any other role gets the row without `mediaUrl`. `omitClipsHiddenFromViewer` (same file, built on `omitMediaUrl`) applies it on every such read: `GET /api/measurements` (every `filterMode`, including the `filterMode=all` history), `GET /api/measurements/:id` and `GET /api/events/:eventId/measurements`. Which rows a requester gets is unchanged: rows of organizations they belong to, and personal (no-organization) rows only to their own athlete or a site admin. The event route only lets event managers, and the owning athlete once results are published, read at all. The unified view strips every clip, because linked accounts can sit in organizations the requester does not belong to; for the requester's own rows this matches the list, which keeps the owner's clips.
3. **Latest-event selection (0148)**: `calculationConfig.sourceSelection = 'latest_event'` on both totals. Only verified scores count. For a date, the latest event wins, ranked by event start time, then event created_at (any event outranks scores without one; entry order decides only when two events tie on both), and a total is computed only when all its source metrics come from that same event. If the latest event is incomplete, the existing total for that date is deleted. There is one total per athlete and date; it takes its organization, team, submitter and verification from the newest score of the chosen event. Totals are recalculated under one advisory lock per (athlete, total, date).
4. **Zero values only for MQ metrics**: 0 is accepted for MQ codes (prefix match in `packages/shared/peer-comparison-exclusions.ts`) whose `site_metrics.validation_min <= 0`, with a range and whole-number check; every other metric keeps the positive-only rule, including existing metrics seeded with `validation_min = 0` (`packages/shared/measurement-value-validation.ts`). On the storage write path (CSV, OCR, review queue) the range rule applies to MQ metrics only; other metrics keep that path's pre-AM-FEAT-015 behavior (no zero or range check, only a finite-number check).
5. **Exclusion from comparisons**: MQ metrics are excluded from peer percentiles, report percentiles / team averages / rankings / composite index, most-improved, benchmarks (create and update) and leaderboards (`packages/shared/peer-comparison-exclusions.ts`).
6. **Event writes via `MeasurementService`**: event data entry goes through the service (unit handling, validation, derived calculator) instead of direct inserts. MQ scores are one row per (athlete, metric, event), edited in place under an advisory lock, with a partial unique index as backstop (0149), and always use the event's calendar date. Event measurements belong to the event's organization, with team context only from the athlete's teams in that organization. Only `POST` and bulk event entries made after results are published notify the athlete or run achievements; the panel save and in-place edits never do. An in-place edit records the editor as submitter (and verifier for coaches and admins). The panel saves one athlete atomically with `PUT /api/events/:eventId/athletes/:userId/movement-quality`, serialized per (event, athlete), recalculating each affected total once; it also clears scores, and there is no per-measurement event `DELETE` route. Frozen events remain frozen.
7. **Notes and UI**: per-pattern notes go in `measurements.notes`. UI is the `MovementQualityPanel` dialog on event data entry.
8. **Coach-only MQ scores and clips**: athletes may not enter MQ scores (R2) or attach clips (R1). Both rules are a role **allowlist**: only `coach`, `org_admin` and `site_admin` may write an MQ code (the `isMovementQualityMetric` predicate, including moving an entry onto an MQ metric) or set a non-empty `mediaUrl`; every other role (athlete, parent, guest) and a missing role are denied. Omitting or clearing `mediaUrl` (null or empty string) is allowed for every role. Enforcement lives in two places. (a) `MeasurementService` (`assertCanEnterMetric`, `assertCanAttachClip`) on create, batch and update, so every route that writes through it is covered: `POST` / `PUT /api/measurements` answer **403** `{ message }`, and `updateMeasurement` fails closed when no role is passed. (b) The storage-based import paths, which write through `storage.createMeasurement` and call `assertCanEnterMetric` themselves: the CSV measurement import and the photo (OCR) import reject a non-allowed MQ row as a **per-row error** in the import result (the request itself succeeds, it is not a 403), checked before athlete matching or creation; `POST /api/import/review-decision` answers **403** for a decision on an MQ item by a non-allowed role and leaves the item pending (that route is currently unreachable, shadowed by `POST /api/import/:type`, which is registered first (#517); the guard applies once the order is fixed). The imports do not take `mediaUrl`. Event measurement routes, including the panel save, are limited to event managers (site admin, or coach / org admin of the event's organization) and map the two permission errors to 403 as a safeguard. The event service enforces the allowlist itself too: it writes through `MeasurementService` with the manager role the route resolves, and a call without a role fails closed. Event writes are limited to users whose membership role in the event's organization is athlete, coach or org admin (400; a per-item error in bulk): parent and guest members are rejected, and so is a site admin who is not a member. The photo (OCR) import cannot import MQ scores at all (its extractor only recognizes timed/jump metrics and it rejects values <= 0), so the zero rule in decision 4 applies to the CSV path, not OCR. In the UI, event data entry renders only for event managers (`canManageEvent` in `packages/web/src/lib/event-permissions.ts`, shared with the event page), and the athlete self-entry forms do not list MQ metrics: `SelfEntryForm.tsx` (My Measurements) and, for athletes, `athlete-measurement-form.tsx`.

Rejected: a dedicated MQI table (duplicates measurement history, permissions and exports); raw-value percentiles for ordinal scores (not meaningful).

## Consequences

### Positive
- MQI reuses measurement permissions, history, audit and derived-metric machinery.
- `media_url` is reusable; exports never select it, and the views that pass rows through strip it.
- Zero-valid metrics are possible without loosening validation for timed/jump metrics.

### Negative
- Redaction is allowlist-by-call-site: a new read path that exposes measurements must use an explicit field list without `mediaUrl` or one of the redaction helpers.
- The three event measurement mutation routes (`POST`, `POST .../bulk`, `PUT .../movement-quality`) share one limiter: STANDARD tier, 100 per 15 minutes per signed-in user (previously MUTATION, 20 per 15 minutes per IP, on POST and bulk); the two reads the panel refetches after each save use the same tier, also per user. The app-wide `/api` limiter (100 per 15 minutes) applies first and is also keyed per signed-in user (anonymous requests per IP, via `ipKeyGenerator`), so staff on one network no longer share a budget. Very large sessions can still reach these limits.
- Down migrations are manual (`apply-manual-migrations.js` skips `*_down.sql`): 0146 down refuses while MQ data or configuration (measurements, goals, report benchmarks, event and organization metric configuration) references the metrics, 0147 down destroys stored links, 0148 down removes latest-event selection, 0149 down drops the unique index.

### Neutral
- Open item M4 (unverified athlete MQ scores never produce a total): with decision 8 an athlete-role session cannot create or edit an MQ score on any write path that exists today (MeasurementService routes, event routes, CSV, OCR, review decision), and MQ scores written by coach / org admin / site admin sessions are verified, so the totals' verified-only rule needs no trigger change. The claim rests on the session role; see the known issues below.
- Known issues left open (pre-date AM-FEAT-015, not fixed here): the session role is taken from the user's first organization, not the organization of the row being written, so a user who is a coach in one organization and an athlete in another is treated as a coach everywhere (#514); `POST /api/measurements` does not restrict parent and guest sessions to their own data for non-MQ metrics (#515); the CSV import has no general athlete block, only the MQ rule (#516); the import review queue is held in memory, is not filtered by organization, and its decision route is shadowed (#517).
- Decided access rules: (1) clip read visibility is the rule in decision 2 (owner, coach / org admin of the row's organization, site admin); a teammate athlete or a parent never receives a clip (`tests/integration/clip-read-visibility.test.ts`); (2) personal (no-organization) measurements are visible only to their athlete and to site admins: coaches do not see them, even in a shared organization (`tests/integration/personal-measurement-isolation.test.ts`).
- Fixed alongside this work although they pre-date it: personal (no-organization) measurements were returned to any signed-in user by `GET /api/measurements?filterMode=personal|all` and `GET /api/measurements/:id`; the event routes accepted athletes from other organizations and stored an event score under the organization of the athlete's single team in any organization (or none); global search returned a teammate's personal and other-organization measurements; org-scoped measurement reads returned clips to every member of the organization, including teammate athletes and parents; event writes accepted parent and guest members (and site admins without membership) as the measured athlete; the app-wide `/api` limiter was shared by every user behind one IP.
- v1 out of scope: score bands, report surfacing, BTB / AM-FEAT-014 quadrant, video upload (URL only), structured hard-fault.
- Manual migration numbers 0144/0145 are reserved for AM-FEAT-016.
